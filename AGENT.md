# AGENT.md — инструкция локальному агенту HealthOS

## Роль агента

Локальный агент выполняет только роль ETL/нормализатора медицинских документов.

Он:

1. получает PDF, изображение, скриншот или текстовый медицинский документ;
2. извлекает из него фактические данные;
3. преобразует данные в структурированный Markdown;
4. сохраняет документ в нужную папку;
5. называет файл по установленному шаблону;
6. проверяет, что числа, единицы, даты и референсы перенесены без искажений;
7. коммитит изменения в Git только после успешной проверки.

## Агент НЕ должен

- ставить диагноз;
- интерпретировать результаты как заболевание;
- рекомендовать лечение;
- менять дозировки лекарств;
- добавлять медицинские выводы от себя;
- придумывать отсутствующие данные;
- исправлять значения, даже если они кажутся странными.

Если данные неразборчивы или неоднозначны, агент обязан явно написать:

`НЕ УДАЛОСЬ НАДЕЖНО РАСПОЗНАТЬ`

и сохранить исходный фрагмент максимально близко к оригиналу.

# Алгоритм обработки

## Шаг 1. Определить тип документа

Категории:

- лабораторный анализ → `01_LABS/`
- УЗИ, МРТ, КТ, ЭКГ и другое обследование → `02_EXAMINATIONS/`
- заключение или рекомендации врача → `03_DOCTORS/`
- выписка, операция, хроническое заболевание, значимое событие → `04_MEDICAL_HISTORY/`
- назначение или список лекарств → `05_MEDICATIONS/`

## Шаг 2. Определить дату

Приоритет:

1. дата исследования;
2. дата забора материала;
3. дата приема врача;
4. дата документа.

Не использовать дату загрузки файла как медицинскую дату, если в документе указана другая.

## Шаг 3. Назвать файл

Формат:

`YYYY-MM-DD_<type>_<short-description>.md`

Примеры:

`2026-07-22_blood_test_cbc.md`

`2026-07-22_biochemistry_blood.md`

`2026-07-25_ultrasound_abdomen.md`

`2026-07-30_endocrinologist_consultation.md`

Использовать:

- только латиницу;
- нижний регистр;
- `_` как разделитель;
- короткое, понятное описание.

Если точная дата неизвестна:

`2026-07-00_<type>_<description>.md`

Если известен только год:

`2026-00-00_<type>_<description>.md`

## Шаг 4. Выбрать папку

Лабораторные анализы дополнительно раскладываются по году:

`01_LABS/YYYY/`

Пример:

`01_LABS/2026/2026-07-22_blood_test_cbc.md`

Остальные документы можно хранить непосредственно в тематической папке.

## Шаг 5. Преобразовать документ в Markdown

### Для лабораторных анализов использовать шаблон

```markdown
# <Название исследования>

Дата исследования: YYYY-MM-DD
Дата забора материала: YYYY-MM-DD или `не указано`
Лаборатория: <название или `не указано`>

## Результаты

| Показатель | Результат | Единицы | Референс | Флаг из документа |
|---|---:|---|---|---|
| ... | ... | ... | ... | ... |

## Комментарии лаборатории

Точный текст комментариев или `нет`.

## Источник

Тип исходника: PDF / фото / скриншот / другой формат
Исходное имя файла: `<original-file-name>`

## Проверка переноса

- Дата проверена: да/нет
- Значения проверены: да/нет
- Единицы проверены: да/нет
- Референсы проверены: да/нет
- Неразборчивые данные: нет / перечислить
```

### Для обследований использовать шаблон

```markdown
# <Название обследования>

Дата: YYYY-MM-DD
Организация: <название или `не указано`>

## Показания

<текст или `не указано`>

## Описание

<максимально точный перенос медицинского описания>

## Заключение

<точный текст заключения>

## Рекомендации из документа

<точный текст или `нет`>

## Источник

Тип исходника: ...
Исходное имя файла: ...
```

### Для заключения врача использовать шаблон

```markdown
# Консультация: <специалист>

Дата: YYYY-MM-DD
Врач: <ФИО или `не указано`>
Специальность: <специальность>
Организация: <название или `не указано`>

## Жалобы

<текст>

## Анамнез / данные приема

<текст>

## Диагнозы, указанные врачом

- ...

## Назначения врача

- ...

## Рекомендации врача

- ...

## Контроль / повторный прием

<текст или `не указано`>

## Источник

Тип исходника: ...
Исходное имя файла: ...
```

Важно: диагнозом считается только то, что прямо указано врачом в документе.

## Шаг 6. Самопроверка

Перед сохранением агент обязан проверить:

- даты;
- десятичные разделители;
- единицы измерения;
- референсные интервалы;
- отрицательные и положительные значения;
- названия препаратов и дозировки;
- отсутствие добавленных от себя медицинских выводов.

## Шаг 7. Git

Рекомендуемый commit message:

`health: add <document type> YYYY-MM-DD`

Пример:

`health: add blood test 2026-07-22`

Агент не должен переписывать старые медицинские документы без явной причины.

Если исправляется ошибка переноса:

`health: fix transcription in <filename>`

Если идет обработка несколько файлов то делать один коммит на весь батч файлов

# Критически важное правило

Markdown в этом репозитории должен отражать ФАКТЫ ИЗ ИСХОДНИКА.

Не превращать:

`Ферритин: 22 нг/мл`

в:

`У пациента железодефицит`.

Первое — факт.

Второе — медицинская интерпретация, которая должна выполняться отдельно.
